# Cloudflare Pages —— ppanel-user-web（用户端）

## 0. 前置条件：前端代码作为独立仓库

为避免路径歧义，前端使用 **frontend 独立仓库**（示例：`ppanel2/frontend`，即 GitHub 上的
`ppanel2/frontend` 仓库；若你的仓库地址不同，替换为实际地址）。

仓库根目录必须包含 [`package.json`](../../../frontend/package.json) 与
[`bun.lock`](../../../frontend/bun.lock)，Cloudflare Pages 才能正确解析 bun workspace 并锁定依赖版本。

## 1. 创建项目

1. Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**。
2. 选择 **frontend 独立仓库**（`ppanel2/frontend`），**不要**选包含 backend/、deploy/ 的整体仓库。
3. 项目名：`ppanel-user-web`。

## 2. 构建配置

| 配置项 | 值 |
|---|---|
| 框架预设 | 无（不选预设） |
| 根目录 | **留空**（仓库根即 frontend/package.json 所在） |
| 构建命令 | `bun install --frozen-lockfile && bun run build --filter=ppanel-user-web` |
| 构建输出目录 | `apps/user/dist` |
| Node 版本 | 20（`NODE_VERSION=20`） |

> 说明：`--filter=ppanel-user-web` 由 turbo 解析，仅构建该包及其 workspace 依赖；
> `@workspace/ui` 无 build 脚本，vite 直接引用其源码，无需预构建。

## 3. 环境变量（Production）

```text
VITE_API_BASE_URL=https://ppapi.lightree.uk
VITE_API_PREFIX=
VITE_CDN_URL=https://cdn.jsdmirror.com
VITE_TUTORIAL_DOCUMENT=true
VITE_SHOW_LANDING_PAGE=true
NODE_VERSION=20
```

> 关键：后端已内置**白名单 CORS**（合法来源见 `ppanel-cors` ConfigMap，支持热重载），不再使用
> Worker 网关/Caddy；前端**直连** `https://ppapi.lightree.uk` 即为 API 域名（后端路由 `/v1/...`）。
> `VITE_API_PREFIX` **必须留空**——后端没有 `/api` 前缀路由（除 edge），且已无 Worker 剥除前缀。
> `VITE_SHOW_LANDING_PAGE=true` 展示落地页，可改为 `false` 直接进登录页。

## 4. 绑定自定义域

项目 **Custom domains** → **Set up a custom domain** → 输入 `users007.lightree.uk` → 激活。

## 5. 说明

- **无需** `_redirects` / Pages Functions 反代（前端直连 `ppapi.lightree.uk`，CORS 由后端处理）。
- SPA 路由回退：仓库已自带 [`public/_redirects`](../../../frontend/apps/user/public/_redirects)
  （`/*  /index.html  200`），vite 构建时复制到 `dist`，Cloudflare Pages 自动生效；
  该规则仅影响前端域名，不影响 API。
- 用户端展示的**订阅地址**由后端配置 `Subscribe.SubscribeDomain` 生成
  （`https://sub.示例域名/v1/subscribe/...`），无需在前端额外配置。
